# Telegram TTN Bot

Telegram-бот для автоматизации заявок на грузоперевозки и подготовки товарно-транспортных накладных (ТТН).

Проект вырос из реальной задачи: водители создают заявки прямо в Telegram, мастера проверяют их, печатают ТТН и ведут реестр пачками по 25 документов. Бот формирует Word/PDF-документы, хранит историю, ведёт аудит действий и делает резервные копии.

> В репозитории используются **демонстрационные данные**. Реальные ФИО, номера машин, организации, Telegram ID, базы данных и токены в публичную версию не включены.

## Возможности

- Роли **водителя**, **мастера** и **администратора**.
- Создание заявки через пошаговый диалог в Telegram.
- Выбор предприятия, водителя, машины, прицепа, даты, точек погрузки/разгрузки и грузов.
- Расчёт стоимости, НДС и массы груза.
- Автоматическая генерация ТТН в Word и PDF.
- Пакетная печать ТТН: выбор заявок, два Word-файла (передние и задние стороны) по 4 экземпляра на заявку и подтверждение печати.
- Полный предпросмотр пакета перед формированием и на финальном экране перед печатью: заявка, накладная, строка реестра и номер ТТН для каждой позиции.
- Выбор заявок сохраняется между перезапусками бота; при отмене пакета выбор восстанавливается для исправления.
- Реестр ТТН пачками по 25 документов; пакетная печать заполняет его с конца, как при одиночной печати.
- Ручные накладные в реестре.
- Печать, отмена печати и повторная печать без потери номера ТТН.
- Мягкое удаление заявок с подтверждением.
- Журнал действий: кто, когда и что изменил.
- Статусы доставки заявок мастеру: доставлено, ошибка, ожидает; недоставленные видны администратору, а водитель видит статус доставки в списке заявок.
- Повторная доставка недоставленных заявок из админ-панели (отдельной заявки или всех сразу) с регенерацией Word-документа.
- Админ-панель: аудит, удалённые заявки, восстановление, экран «Доставка заявок» и «Состояние бота» с проверкой мастеров, БД, пачек и бэкапа.
- Мониторинг автобэкапа: статус таймера `ttn_backup.timer`, возраст последней копии (порог 48 часов), проверка целостности и уведомление администратору при старте при проблеме.
- Резервное копирование SQLite через backup API, проверка целостности и восстановление; на сервере — ежедневный автобэкап.
- Регистрация водителей и мастеров.
- Тесты на ключевые сценарии.

## Структура проекта

```text
Bot.py                     точка входа
config.py                  настройки и глобальные состояния
database.py                справочники и демо-данные
orders_db.py               SQLite: заявки, пачки, аудит, ручной реестр
word_filler.py             заполнение Word-шаблона ТТН
batch_word.py              сборка пакетных Word-файлов (перед/зад)
batch_print.py             выбор заявок и подтверждение пакетной печати
registry_filler.py         генерация реестра
backup.py                  backup / verify / restore
health.py                  проверка мастеров, доставки, БД и последнего бэкапа
driver_*.py                сценарии водителя
master_*.py                сценарии мастера
registry.py                печать и реестр ТТН
admin_menu.py              управление справочниками и аудит
utils.py                   расчёты, числа словами, форматирование
tests/                     pytest-тесты
assets/                    демонстрационный шаблон ТТН
```

## Быстрый старт

```bash
python -m venv .venv

# Linux/macOS
source .venv/bin/activate

# Windows
# .venv\Scripts\activate

pip install -r requirements-dev.txt

cp .env.example .env
# заполните BOT_TOKEN и YOUR_TELEGRAM_ID

python Bot.py
```

Для генерации документов нужен шаблон. В репозитории уже есть демонстрационный шаблон `assets/Шаблон_ТТН_демо.docx`; бот использует его, если нет `Шаблоны/Шаблон_ТТН.docx`. Чтобы положить демо-шаблон в рабочую папку:

```bash
python create_template.py
```

Скрипт не перезаписывает существующий `Шаблоны/Шаблон_ТТН.docx`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `YOUR_TELEGRAM_ID` | Telegram ID администратора |
| `COMPANY_NAME` | название организации для документов |
| `COMPANY_SHORT_NAME` | короткое название для заголовка реестра |
| `REGISTRY_MASTER_NAME` | подпись мастера в реестре |
| `RELEASE_ALLOWED_BY` | подпись «Отпуск разрешил» в ТТН |
| `AIAI_API_KEY` | необязательный ключ для `ai_worker.py` |

`.env` исключён из git. В репозитории есть только `.env.example`.

## Данные и безопасность

В git **не попадают**:

- `.env` и токены;
- `orders.db`, `acts.db` и WAL-файлы;
- `data/` с реальными справочниками;
- `masters.json`, `last_orders.json`;
- `backup/`;
- `Шаблоны/`, `Результат/`, `Результаты/`;
- виртуальные окружения и кэши.

Для production рекомендуется держать данные вне репозитория или в игнорируемых каталогах, а в git хранить только код и демонстрационные шаблоны.

## Тесты

```bash
pytest -q
```

CI настроен в `.github/workflows/tests.yml`.

### Самопроверка пакетной печати

```bash
python self_test_batch.py
```

Скрипт использует временную базу и тестовые заявки, не трогает боевые
`orders.db` и `data/`. Он формирует пакет из 10 заявок, проверяет Word,
порядок страниц, строки реестра 25–16, подтверждение и откат. Образцы файлов
и отчёт сохраняются в `Результат/Самопроверка_пакетной_печати_...`.

Для проверки на рабочем шаблоне:

```bash
python self_test_batch.py --template "Шаблоны/Шаблон_ТТН.docx"
```

## Деплой на VPS

Код и рабочие данные разделены. На сервере можно обновлять код через `git pull`, не затрагивая `.env`, базы и справочники:

```bash
cd /home/loktionov/ttn_bot
git pull --ff-only
systemctl restart ttn_bot.service
```

Перед обновлением рекомендуется сделать резервную копию:

```bash
./venv/bin/python backup.py
./venv/bin/python backup.py --verify backup/YYYY-MM-DD
```

Восстановление:

```bash
./venv/bin/python backup.py --restore backup/YYYY-MM-DD
```

На сервере ежедневный автобэкап запускается таймером `ttn_backup.timer`
(03:00 UTC). Проверить расписание и последний запуск:

```bash
systemctl list-timers ttn_backup.timer
systemctl status ttn_backup.service
```

После обновления откройте в боте «Админ-панель → 🩺 Состояние бота»:
экран показывает размер БД, активные пачки, статусы доставки, последний
бэкап и доступность чатов мастеров.
